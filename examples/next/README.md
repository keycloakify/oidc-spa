# Next.js example

A Next.js App Router application with oidc-spa authentication. The setup follows the official `create-next-app` 16.3.4 starter: TypeScript, ESLint, Tailwind CSS 4, and Turbopack.

## Getting started

Use Node.js 24 LTS (minimum 20.19).

```bash
npx gitpick keycloakify/oidc-spa/tree/main/examples/next start-oidc
cd start-oidc
npm install
npm run dev
```

Open http://localhost:3000. Yarn and pnpm also work: use `yarn install` / `yarn dev` or `pnpm install` / `pnpm dev`.

Installation creates `.env.local` from `.env.local.sample` if it does not exist. Configure your issuer and client there, or set `NEXT_PUBLIC_OIDC_USE_MOCK=true` to try the app without an identity provider. Restart the development server after changing the configuration. `NEXT_PUBLIC_*` values are embedded in the client build, so configure them before building for deployment.

From the oidc-spa repository root, `yarn start-next-example` builds and copies the local library before starting this example.

## Commands

-   `npm run dev` — start the development server with Turbopack.
-   `npm run build` — create a production build.
-   `npm start` — serve the production build.
-   `npm run typecheck` — generate Next.js route types, then check TypeScript.
-   `npm run lint` — run the standard Next.js Core Web Vitals and TypeScript rules.

`next-env.d.ts` and `.next/` are generated by Next.js and are not tracked. The root layout uses `next/font/google`, as in the official starter; a production build downloads the Geist fonts.

## OIDC integration

See the [Next.js integration guide](https://docs.oidc-spa.dev/integration-guides/next.js).

-   `instrumentation-client.ts` runs `oidcEarlyInit()` before the application becomes interactive.
-   `lib/oidc.tsx` configures authentication and adapts `OidcInitializationGate` and `withLoginEnforced` to the App Router.
-   `app/layout.tsx` wraps the application in `OidcInitializationGate`.
-   Protected route layouts use `withLoginEnforced`; components that consume authentication are Client Components.

Authentication happens in the browser. The Next.js server cannot use this client session to authorize server-rendered content. This example therefore uses a SPA authentication model inside the App Router. APIs must validate access tokens independently.

## Routes

-   `/` — public landing page with login/logout controls.
-   `/protected` — guarded page with profile information and authenticated API requests.
-   `/admin-only` — guarded page with a role check.

## Dependencies

Direct dependencies are pinned to compatible versions from the current Next.js starter, except `oidc-spa`, which stays on `latest`. TypeScript and ESLint follow the starter's major versions and its lint plugins' compatibility requirements. `pnpm-workspace.yaml` allows the native resolver build used by the lint tooling (pnpm 10.26+). No lockfile or package manager is imposed on users; transitive dependencies can still change between fresh installations.
