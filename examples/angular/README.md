# Angular

An Angular SPA with oidc-spa authentication, an application user model, and protected routes. The tooling follows the standalone, zoneless project generated by [Angular CLI](https://angular.dev/tools/cli/setup-local) 22.1.7, including its Vitest test runner.

## Getting started

Use Node.js 24.15+ (24.x LTS). Angular also supports Node.js 22.22.3+ (22.x) and 26+.

```bash
npx gitpick keycloakify/oidc-spa/tree/main/examples/angular start-oidc
cd start-oidc
npm install
npm start
```

Open http://localhost:4200. Yarn and pnpm work too: use `yarn install` / `yarn start` or `pnpm install` / `pnpm start`.

Configure the issuer and client in `src/app/app.config.ts`. Define the application user in `src/app/services/oidc.service.ts` with `oidcSpa.withUser()`. See the [user abstraction documentation](https://docs.oidc-spa.dev/features/user).

`src/main.ts` runs `oidcEarlyInit()` before dynamically loading Angular through `src/main.lazy.ts`. Keep this boundary so OIDC callback handling can finish before the application boots.

## Commands

- `npm start` — start the development server with live reload.
- `npm run build` — create a production build in `dist/angular/browser`.
- `npm run watch` — rebuild the development output when files change.
- `npm test` — run Vitest in watch mode.
- `npm test -- --watch=false` — run the tests once, without a browser or identity provider.
- `npm run ng -- generate component my-component` — generate an Angular component.

Deploy `dist/angular/browser` to a static host configured to serve `index.html` for application routes.

Direct dependencies are pinned to compatible versions from the current Angular CLI setup; `oidc-spa` stays on `latest`. No lockfile or package manager is imposed on users. `pnpm-workspace.yaml` allows the native build scripts used by Angular CLI (pnpm 10.26+). Transitive dependencies can still change between fresh installations.
